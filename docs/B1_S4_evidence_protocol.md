# R1.3 B1-S4 — 证据引用（方案 C）与协议增强（方案 D）详细设计

**日期**: 2026-08-13
**依据**: `docs/R1.3_PLAN.md` §3（方案 C/D）、`docs/B1_S1_root_cause_analysis.md`
**范围**: 设计方案文档；不执行代码/推理/数据操作

---

## 1. 目标

1. **可审计性（方案 C）**: 判定输出附带 evidence 引用，使 False REL 可追溯判定理由（R1.3 目标 4：Shadow 级可审计率 ≥ 80%）；
2. **协议增强（方案 D）**: 推理侧强化"内容证据否决表层相似"指令，在不修改冻结数据的条件下降低 over-recall。

## 2. 双协议设计

| 模式 | 用途 | max_tokens | 输出格式 |
|---|---|---|---|
| 判定模式 | valid 评估 / 批量判定（保持 R1.2 口径可比） | 4 | `REL` / `IRREL` |
| **审计模式** | Shadow 验证 / 可审计性评估 | 64 | `REL|IRREL\nEVIDENCE: <path>:<片段>` 或 `IRREL\nEVIDENCE: none` |

- 判定模式维持 R1.2 协议（acc 0.95 / False REL 1 基线可比）；
- 审计模式仅在 Shadow 类场景启用，两模式判定结果需一致（稳定性约束，见 §5）。

## 3. 证据格式规范（方案 C）

```
决策: REL
证据: qxen/packet_builder.py:142: "def dispatch(self, req): ..."   # REL 必须给出候选内证据片段
```
```
决策: IRREL
证据: none   # IRREL 不要求证据（候选无相关证据）
```

规则：
1. **REL 必须有证据**：`EVIDENCE` 字段引用候选内容中的具体行/片段（路径:行号:摘录），且该片段须真实存在于候选内容（有效性校验）；
2. **IRREL 证据为 none**：允许空证据，但判定一致性要求 IRREL 样本不得输出疑似 REL 证据；
3. 证据解析：`决策: (REL|IRREL)` 首行 + `证据: ...` 次行，正则解析，解析失败记 `EVIDENCE_INVALID`。

## 4. 可审计性评估维度

| 维度 | 定义 | 目标 |
|---|---|---|
| 判定-证据一致性 | REL 样本均有有效证据；IRREL 样本证据为空 | 100%（25 样本） |
| 证据有效性 | 证据片段在候选内容中可检索（子串/行号命中） | ≥ 80% |
| **可审计率** | 判定 + 证据均解析成功且有效的样本占比 | **≥ 80%**（Shadow 5 条 4/5） |
| 模式稳定性 | 审计模式与判定模式标签一致率 | 100%（25 样本） |

## 5. 协议增强（方案 D）设计

- 审计模式 prompt 追加一行判定准则（推理侧，不触碰冻结数据）：
  > 「候选与目标的关联仅以候选内容中的证据为准；名称/路径相似（如 neighbor/_v2/同名存根）若无内容证据，不构成相关。」
- 该准则面向 R12-VALL-0005 类表层相似候选，与 R1.3 根因（内容证据否决表层相似）对齐；
- 与方案 B（校准）独立可叠加：校准作用于判定模式概率，协议增强作用于审计模式生成。

## 6. 实现与冻结资产边界

- 新增 `scripts/r1.3/eval_audit.py`（B4 批次实现），复用 R1.2 协议模板 + 审计模式参数；
- **冻结资产不动**：R1.2 adapter（sha256 `0c0ead0d`）、R1.1 冻结数据、R1.2 数据、既有评估脚本与报告均不修改；
- 审计模式输出 JSON：`{id, decision, evidence, evidence_valid, parsed_ok, mode_stable}`。

## 7. 验收标准

- [ ] 审计模式在 Shadow 5 样本上全部解析成功（parsed_ok=1，含 IRREL 的 `证据: none`）；
- [ ] 可审计率 ≥ 80%（4/5），判定-证据一致性 100%；
- [ ] 审计模式与判定模式标签一致率 100%（模式稳定）；
- [ ] 证据有效性校验通过率 ≥ 80%；
- [ ] 若 REL 误判（如 R12-VALL-0005）仍存在，其证据字段须暴露"错误引用/存根内容"，实现可审计（即使误判未消除，审计仍成立）。

## 8. 风险与限制

- 放宽 max_tokens（4→64）可能改变输出分布 → 模式稳定性约束（§7 第 3 条）用于检测并如实记录偏差；
- 证据有效性校验需按行/子串匹配候选内容，候选为存根时证据摘录可能极短（如仅函数签名行）—— 有效性校验规则需明确"存在即可，不要求语义充分"；
- 审计模式对 IRREL 要求输出 `证据: none`，与"模型倾向多说话"特性冲突，解析规则需容错（如空证据行即视为 none）。
