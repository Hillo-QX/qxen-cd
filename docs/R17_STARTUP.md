# QXEN-CD R1.7 阶段启动文档

**日期**: 2026-08-13
**阶段**: R1.7（评估集扩展 → 暴露新失败模式 → 模型侧升级决策）
**起点**: R1.6 闭环（批量预测入口 + 双字段审计，39 条 acc=1.0 零回退）

---

## 1. 核心目标

**一句话目标**: 将评估集从 39 条扩展至 ≥70 条（覆盖 7 类缺口 G1-G7），全部经 R1.6 批量预测入口以 decide() 判定验证，输出新失败模式清单，据此完成"方案C 模型侧升级是否启动"的实证决策。

**前置结论（T372 分析）**:
- 当前 39 条全对、无错误样本 → 无法定位模型侧缺陷 → 必须先扩大评估集暴露新失败模式；
- 方案C（特征注入式微调）在 R1.3 已实证失败（acc0.25/可审计率5%，模型无法稳定遵循两行格式），需两行格式训练数据 + 更大评估集方可重试；
- 因此 R1.7 顺序为: **扩展评估集（第一步）→ 失败模式分析 → 方案C 可行性决策（第二步）**。

## 3. 评估集扩展方案

### 3.1 扩展维度（对应缺口 G1-G7，新增 31-51 条）

| 维度 | 缺口 | 样本类型 | 数量 |
|---|---|---|---|
| D1 tie 平局样本 | G1 | p_first ∈ [0.40, 0.45) 且 tie 触发（logits 差 <0.05），验证 decide() 下 tie→REL 兜底 | ≥4 |
| D2 关系类型扩展 | G2 | CONSTRAINT（≥4）、CAUSAL（≥3）、新增关系变体 | ≥8 |
| D3 新跨域 | G3 | 金融交易（trade/order）、电商（order/inventory）、客服（ticket/agent）各 3-4 条 | ≥10 |
| D4 对抗新变体 | G4 | 编码伪装（UTF-8 BOM/全角字符/零宽字符）、时间戳近似（同日不同时）、软链路径、大小写变体 | ≥8 |
| D5 mid 带边界 | G5 | p_first 落在 0.15±0.02 与 0.45±0.02 边界两侧（高低置信带切换边缘） | ≥4 |
| D6 超长内容 | G6 | content >100KB 的大文件（配置/日志/报告），验证规则性能与判定 | ≥2 |
| D7 路径元数据型 | G7 | 文件缺失/路径为目录/URL 相对路径/Windows 风格路径 | ≥4 |

### 3.2 数据质量要求（沿用 R1.4/R1.5 协议）
- 与既有 39 条及 R1.2/R1.3 全部训练评估集**零重叠**（批内唯一 + 组合/文本重叠 QA）；
- 每个样本含完整 meta（id/task/candidate_path/materiality_relation/scenario_type/label）；
- 标注依据可溯源（真实片段优先，合成样本需声明）。

## 4. 模型侧升级候选方案评估

| 方案 | 说明 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| **方案C 重试**（特征注入式微调） | 新增"判定+证据"两行格式训练数据（R1.3 失败根因：模型仅训单标签，无法稳定输出两行） | 从模型侧吸收规则知识，降低规则枚举维护成本；随域增长可扩展 | R1.3 实证失败模式；微调可能破坏 39 条基线（需回归护栏）；需先造两行格式数据 | **推荐（R1.7 第二步）**：以扩展后评估集为回归基准，两行格式数据先行，acc/可审计率双门槛 |
| 规则增强（decide() 扩展） | 新增 F3 元数据特征/F4 路径结构特征 | 零训练、可审计性不变 | 不改 decide() 本体 → 需新模块组合，随域增长枚举维护成本上升（正是要回避的问题） | 备选（仅当方案C 不可行） |
| 集成/投票 | 多规则+多阈值集成 | 稳健性提升 | 复杂度高、收益不明、审计链路复杂 | 不推荐 |
| **HTTP/CLI 封装** | 批量入口封装为命令行/服务 | 工程便利 | 不改变判定能力，不暴露新失败模式，对准确率无贡献 | 低优先（延后或并行） |

## 5. 优先级对比结论

**评估集扩展（D1-D7）> 方案C 模型侧升级（重试）> HTTP/CLI 封装**

理由: 当前 39 条 acc=1.0 无错误样本，模型侧升级缺少失败驱动；扩展评估集暴露新失败模式后才能确定方案C 是否值得、以何种数据形态重试。HTTP/CLI 封装纯工程便利，不提升判定能力，排在最后。

## 6. 验收标准（客观可度量）

1. **扩展评估集 ≥70 条**: `data/r17_extended/` 下存在扩展集（新增 ≥31 条），QA 报告显示与既有 39 条零重叠；
2. **7 类缺口全覆盖**: G1-G7 每类至少 2 条样本（D1-D7 全部落地）；
3. **判定验证完成**: 全部扩展样本经 R1.6 批量入口（decide() 链路）判定，输出 label+reason 双字段，acc/FR/FI 记录于 reports/r1.7/，且既有 39 条零回退（acc=1.0 保持）；
4. **失败模式报告**: 新失败样本（如有）逐条溯源分析（根因 + decide() 局限 + 处置建议），作为方案C 决策输入；
5. **方案C 决策输出**: 基于失败模式报告给出方案C 启动/暂缓的明确结论与理由。

## 7. 停止条件

- 任一验收标准（§6）无法客观验证；
- 需要修改冻结路径（含 decide() 本体、r16_batch_predict.py）；
- 需要调用 Ollama 或在本阶段进行模型训练；
- 扩展后失败模式显示规则枚举维护成本不可控且方案C 前置数据（两行格式）不可构造 → 升级决策。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 合成样本与真实轨迹语义偏差 | 沿用 R1.4/R1.5 QA 零重叠协议 + 真实片段优先 + 标注溯源 |
| 新域过多导致 F1 声明路径解析失效 | 失败样本逐条归因，区分"规则局限"与"数据标注问题" |
| 方案C 重演 R1.3 失败 | 两行格式训练数据先行 + 扩展集回归护栏 + acc/可审计率双门槛 |
| 扩展集过大超出单任务批次 | 按维度分批生成（D1-D7 各成独立批次，逐批 QA） |
